# 云端日报运行方式

日报由 GitHub Actions 每天北京时间 08:05 运行。它先启动项目自带的无头 Chromium，再执行采集、原文日期与正文核验、去重、日报生成和内容校验，最后把静态网站发布到 GitHub Pages。

日报统计周期固定为前一天 08:00 至当天 08:00。来源读取受限或原文无法核验时，本轮仍会发布已核验内容，并在网站中提示来源覆盖状态。

首次上线只需：

1. 将此目录推送到一个 GitHub 仓库。
2. 在仓库 Settings → Pages 中将 Source 设为 GitHub Actions。
3. 定时任务不使用 `OPENAI_API_KEY`，也不需要充值。线索来自品牌官网、工信部、汽车之家、懂车帝、登记媒体的公开列表，以及直连失败时的必应搜索；标题由本地规则从已核验正文生成。
4. 官方微博先用公开访客会话读取时间线。访客会话被限流时，可在仓库 Secrets 配置可选的 `WEIBO_COOKIE`（从已登录 weibo.com 请求头复制整段 Cookie，调用 `weibo.com/ajax/statuses/mymblog`，不要写入仓库）。未配置或仍读不到时，账号标成“公开时间线暂不可读”，只记警告，不阻断发布。
5. 在 Actions 页面手动运行一次“更新汽车日报”，确认 Pages 地址生成。成功时「采集、核验与生成日报」为绿色，随后会出现一次 `chore: update automotive daily report` 提交，并且 `deploy-pages` 完成。站点首页能打开最新一期日报。

之后不需要打开电脑；GitHub 的定时任务会自行运行。需要补跑时，打开 Actions →「更新汽车日报」→ Run workflow。只有官网和政策列表都没读到，或核验/生成步骤本身失败时，该工作流才会以失败结束并停止发布。
