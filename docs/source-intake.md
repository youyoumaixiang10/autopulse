# 汽车日报来源输入清单（第一轮）

## 结论

日报不能只依赖一家汽车媒体。品牌新品、权益、官方活动及政策应优先使用品牌、官方自媒体或政府一手来源；行业媒体用于发现候选和补充行业影响，但不单独证明核心事实。

## 来源状态

- `pilot`：列表页清晰，可作为第一批自动输入进行适配验证。
- `route-check`：官网可确认存在，但需进一步检查动态加载方式或具体资讯路径。

## 覆盖底线

15 个重点品牌均须同时具备三条线：至少一个品牌官网入口、已核验的官方自媒体账号，以及汽车之家/懂车帝等垂直媒体的候选发现入口。当前已完成官网和垂直媒体入口覆盖；15 个重点品牌的官方微博入口均已逐个核验名称、UID 和蓝 V 并接入。公众号、抖音、小红书与品牌 App 仍需逐项接入；微博主页也会受置顶、分页和可见范围影响。系统会分别输出三层的就绪度，不能把“入口存在”写成“全面覆盖”。

## 首批自动输入

1. 比亚迪新闻中心：覆盖比亚迪及腾势的集团/品牌动态。
2. 理想汽车媒体中心：覆盖产品发布与月度交付等官方信息。
3. 零跑汽车资讯新闻：覆盖新品和公司动态。
4. 乐道最新动态：覆盖车型上市、预售与交付节点。
5. 阿维塔新闻中心：覆盖车型、技术、用户活动和营销合作。
6. 中国长安汽车官网：补充阿维塔、深蓝、启源的集团级动作；具体新闻路径仍需适配确认。
7. 特斯拉中国官网与官方微博：覆盖产品、权益、技术和品牌官方信息。
8. 工业和信息化部政务公开：覆盖车型公告、减税目录、行业标准和政策。
9. 蔚来官网、岚图汽车官网、深蓝汽车资讯：分别覆盖三个此前未独立登记的重点品牌。

## 自动读取试点

理想汽车媒体中心、阿维塔新闻中心、乐道最新动态、蔚来新闻中心、极氪官方新闻和工信部政务公开已具备稳定的读取方式，先读取最近 7 天的标题、发布日期和原文链接，生成候选项。极氪的官方新闻接口可读取置顶及分页列表，出现近 7 天的新条目时再读取对应的官方详情正文；蔚来通过浏览器读取动态列表；工信部仅保留汽车相关的政策、公告和标准。候选项尚未等同于日报内容：需完成事件合并、重要性判断和摘要生成后才能发布。

## 官方自媒体信号层

新品预热、发布会、限时权益、线下活动与营销合作，常常首先出现在品牌官方自媒体。重点品牌均需核验并接入其官方微信公众号、微博、抖音、小红书及品牌 App；以品牌确实开通的平台为准，不把未认证账号纳入采集。

每条自媒体候选都保存账号名称、原帖链接、发布时间、首图及原文标题。发布时优先保留原帖链接；若同一事件随后出现官网详情，自动将其合并为一条新闻，并以官网链接作为主来源。

## 为什么参考日报会比本系统更密

2026-10-11 08:00 至 2026-10-12 08:00 这一期偏薄，主要不是编辑故意少写，而是线索没有进到可核验原文：

- 新浪、易车、财联社、IT之家、盖世、太平洋、搜狐、网易等登记媒体原先只从 Bing 结果里取 `li.b_algo h2 a`，并且检索式带上“某年某月某日”。Bing 经常返回 0 条，系统就把“检索没命中”写成“未发现线索”。现在这些媒体优先读各自公开列表或 RSS，Bing 只给直连失败的来源做补充，并放宽结果链接解码。
- 15 个官方微博原先只读需要登录的桌面页面，未登录时 15/15 失败，帖文没有进入日报。现在先走公开访客时间线，可选 `WEIBO_COOKIE` 作为后备；两者都没有时记为降级，不阻断发布。
- 小米、岚图、鸿蒙智行、启源、腾势官网当前没有可公开抓取的新闻列表（资讯在 App 或官方微博，腾势集团稿在比亚迪新闻中心）。特斯拉读中国博客列表。吉利银河新闻接口能返回标题，但详情仍是不可公开访问的 Sitecore 路径，因此只在出现真实 https 详情链接时入库。
- 懂车帝公开首页可以出标题，正文和完整日流仍受登录限制；正文读取超时已放宽并重试一次，减少已发现链接被丢掉。
- 页面仍用原先的短摘要卡片和品牌分组。采集变密只增加可核验条目，不把导语改成长摘录。没有核验到的事实不会补写。

## 垂直媒体候选层

汽车之家资讯和行业频道可用于发现新车、行业、价格与市场变化；懂车帝资讯可用于发现新车、行业和热度信号。当前已自动读取汽车之家资讯，并按重点品牌标注候选；候选保留媒体原文标题和链接，但不把 URL 中的月份伪装成发布日期。它们进入候选池后，涉及上市时间、价格、权益、销量、政策和产品参数的关键表述，优先回到品牌官网、官方自媒体、政府或公告原文核实。

没有一手原文但具有报道价值的内容可以发布，详情页须显示“媒体报道”，保留媒体原链，不写成“品牌官宣”。

## 第二批适配

鸿蒙智行、极氪、小米汽车、吉利银河、长安启源、腾势和特斯拉官网首页均适合监测产品和权益变动，但页面可能依赖动态加载或没有独立资讯列表。先把它们作为候选发现源，抓到候选后必须回到官方详情页确认。

## 仍需补足的信号

营销传播、线下活动、权益的首发信息常出现在品牌 App、微信公众号、微博等官方账号。官网采集不能完整覆盖这部分。第二阶段需要为每个重点品牌增加官方社媒/应用来源，并标注来源平台、公开时间和原始链接。

## 自动生成规则

1. 定时读取官网、官方自媒体、政府与垂直媒体，存为候选项，保留原始标题、时间、链接、账号/媒体名称和来源类型。
2. 按品牌、车型、动作类型和发布时间去重；同一事件合并多信源，并优先保留一手链接。
3. 官方与政府来源优先自动进入日报；垂直媒体的候选需检查一手佐证。媒体预计、信息冲突或缺少时间/价格范围的候选进入待核实。
4. 每天生成日报时，抽取重要摘要、品牌动态、行业信号，并同步更新新车一览。
5. 已完成解析且结构稳定的来源做内容变更监测；未完成解析的来源先做连通性检查，并在就绪度中明确显示为“待适配”，不把随机页面变化误报为新闻。

## 当前自动运行链路

`npm run run-daily` 会顺序完成官方来源采集、媒体发现候选落库、日报数据构建、来源连通检查和覆盖就绪度检查。日报构建会更新当日涉及的归档，不删除历史日期。应用内已设置每日早上自动运行；无异常时不打扰，只有采集、校验或重要候选需要人工核验时才提醒。
